# Migrating from XcodeGen (`project.yml`) to `project.xcproj`

## Format Conversion (Any `.xcodeproj`)

```sh
xcodebuild -project App.xcodeproj -convert-project xcproj   # pbxproj -> JSON
xcodebuild -project App.xcodeproj -convert-project pbxproj  # JSON -> pbxproj
```

## Migration Procedure

1. Generate a clean project from the current spec: `xcodegen generate`.
2. Snapshot baseline resolved settings for each target and configuration:
   ```sh
   xcodebuild -project App.xcodeproj -list
   xcodebuild -project App.xcodeproj -target <Target> -configuration Debug -showBuildSettings > /tmp/before-debug.txt
   ```
3. Convert to JSON: `xcodebuild -project App.xcodeproj -convert-project xcproj`. Existing targets (including test targets) survive conversion intact.
4. Verify canonical format, resolved settings parity, package identities, and tests:
   ```sh
   xcrun xcprojformatter App.xcodeproj | diff -u App.xcodeproj/project.xcproj -
   xcodebuild -project App.xcodeproj -target <Target> -configuration Debug -showBuildSettings > /tmp/after-debug.txt
   diff -u /tmp/before-debug.txt /tmp/after-debug.txt
   xcrun xcodeproj pkg list                                                       # check package identities (not XcodeGen aliases)
   xcodebuild test -scheme <Scheme> -destination 'platform=iOS Simulator,id=<UDID>'   # or platform=macOS
   ```
   Get `<UDID>` from `xcrun simctl list devices available`.
5. Pin CI and team minimum Xcode to 27.0+ (27.2+ if CI runs `xcrun xcodeproj` or `xcprojformatter`) and update any scripts/fastlane jobs that reference `project.pbxproj`.
6. Update `.gitignore`: replace `*.xcodeproj` with `xcuserdata/` and `*.xcodeproj/project.xcworkspace/xcuserdata/`.
7. Commit `<App>.xcodeproj/project.xcproj`, `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, shared schemes under `xcshareddata/xcschemes/`, and any XcodeGen-generated `INFOPLIST_FILE` or `CODE_SIGN_ENTITLEMENTS` files (check `info:`, `entitlements:`, `fileGroups`, and `options.postGenCommand` in `project.yml`).
8. Remove `project.yml` and `xcodegen` steps from CI/mise tasks.
9. **Optional: adopt synchronized folders.** Conversion preserves XcodeGen's explicit `PBXGroup` trees, so new files are not auto-discovered until you opt in. Move `.xcconfig` files out of the source root first, confirm the target has a `sources` phase, add and include the synchronized folder (`group add <Dir> --filesystem-path <Dir>` + `group include --group /<Dir> --target <T>`), remove the old explicit group, and check file counts with `target info --target <T>`.

## Post-Migration Edit Mapping (`project.yml` -> `xcrun xcodeproj`)

`xcodebuild -convert-project xcproj` preserves existing `settingPresets`, `options.deploymentTarget`, `sources[].excludes`/`includes`, `sdk:`/`framework:`/`weak:` dependencies, and target-level `configFiles`. Use this table for subsequent edits:

| XcodeGen (`project.yml`) | Native replacement |
| --- | --- |
| `packages:` (remote / local) | `pkg add <url> --from <ver>` / `pkg add-local <path>` |
| `dependencies: [{ package: P, product: X }]` | `pkg link X --package <id> --target T [--embed]` (`<id>` is from `pkg list`, not the XcodeGen alias; omitted `product:` -> `--product P`) |
| `dependencies: [{ target: Dep }]` | `target add-dependency T Dep`; to link/embed a framework, get the phase index `<N>` from `target info --target T`, then `group include Dep.framework --group /Products --target T --phase <N>` |
| `sources: [path: App]` | `group add App --filesystem-path App` + `group include --group /App --target T` |
| `settings.base` / `settings.configs.Debug` | `setting set` (or `set-multi`) with optional `--config Debug` |
| `configFiles:` | Regular group (`group add` + `group add-file`) + `config set ... [--target T] [--config Debug]` |
| `preBuildScripts` / `postBuildScripts` | `target phase add-script --target T ...` + `target phase move` |
| `schemes:` | Auto-generated by `xcodebuild` or XML in `xcshareddata/xcschemes/` (`xcrun xcodeproj` does not edit schemes or `.xcworkspace`) |
